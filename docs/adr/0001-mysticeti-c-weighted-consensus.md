# ADR 0001: Paper-faithful Mysticeti-C with weighted stake thresholds

**Status: DRAFT — NOT ACTIVATION READY / NOT A COMPLETE FORMAL PROOF**

**Decision scope:** consensus protocol design only

**Validation owner:** orchestrator; Oracle review follows factual-alignment review

**Implementation gate:** consensus implementation is blocked pending resolution of the open proof/specification obligations below. Activation is not authorized; full safety review and Gate 1 remain required before any implementation or activation.

This ADR records a selected design hypothesis, not a claim that the weighted adaptation is proven safe, live, or implemented. In particular, the current one-authority configuration is trusted/non-BFT. No activation or network behavior changes are authorized. Do not implement consensus solely on the basis of this ADR; the direct-candidate closure and cross-view safety questions currently block implementation.

## 1. Context and scope

The project describes its architecture as a Mysticeti-style DAG consensus path feeding committed sub-DAGs to execution (`docs/ARCHITECTURE.md`, “High-level flow” and “Reward path”). The current implementation findings summarized in the task research are materially short of Mysticeti-C: the committer has one hash per leader rather than a candidate set; causal support/certificates and authenticated wire-vote evidence are absent; storage can index multiple hashes but author-round lookup returns one; skip outcomes are not persisted; the current loop can scan past an undecided slot; and the current node uses a singleton committee. These are design and integration gaps, not isolated tie-break bugs.

This ADR selects a paper-faithful Mysticeti-C rule family with a weighted stake interpretation. It does **not** select Sui’s newer direct-r+1/Q plus indirect-V leader-slot rule. It defines the intended vocabulary and predicates, and identifies proof and implementation obligations. It does not settle transaction execution, networking, committee governance, or deployment.

Alternatives considered:

* **First-arrival or hash-min candidate:** rejected. Neither is a safe standalone rule when validators may have different partial DAG views; arrival ordering can diverge and a local hash choice does not establish a common decision.
* **Sui newer direct/indirect leader-slot rule:** not selected. The user selected the NDSS paper’s Mysticeti-C support, certificate, direct decision, and committed-anchor rule family.
* **Unweighted/quorum-count model:** not selected. The project’s adopted model is stake-weighted with fixed epoch membership and explicit identity deduplication.
* **Paper’s direct-skip prose alone:** not selected as the executable shortcut. Its relationship to the printed `SkippedProposer` helper is ambiguous in equivocation/empty-slot cases. This ADR adopts the printed-helper rule as an explicit project adaptation described below.

## 2. Terms and parameters

This scope uses a **static epoch 0**: it fixes the committee, authority IDs, verification keys, positive stake per authority, and proposer schedule. The schedule construction and any bounded recurrence/window property needed for progress are open; fixing an epoch and satisfying `B < W/3` alone does not guarantee useful schedule windows. There is no epoch transition in this scope; committee rotation and transition rules are deferred and remain proof/specification obligations before any future transition is usable. Let `W` be the checked, nonzero sum of epoch-0 committee stake, and let `B` be the maximum Byzantine stake. The selected fault assumption is `B < W/3`. All arithmetic, membership, identity uniqueness, and epoch binding must be validated; overflow, duplicate authority IDs/keys, zero stake, or mixed-epoch evidence invalidates the evidence rather than weakening a threshold.

The stake thresholds are:

* `Q = floor(2W/3) + 1` — the selected weighted quorum threshold.
* `V = floor(W/3) + 1` — **not a decision threshold** in this paper-faithful weighted adaptation.

A **slot** is `(authority, round)`. A **candidate** is a signed block identified by `(authority, round, digest)`. A scheduled proposer slot may have no candidate, one candidate, or multiple candidates (equivocation); a slot is not represented by only one digest. Distinct-author counts are by epoch authority identity, never by block count, key aliases, or repeated references. Deduplicate within each candidate/evidence set. An equivocator can appear in candidate-specific support for one candidate and non-support for another; those are separate sets, not an extra vote within either set.

**Parent-edge round invariant (selected requirement):** every parent reference from a block in round `s` must name a block in a strictly earlier round `< s`. For every counted-valid ordinary block `x` in round `s>0`, its valid **direct parents in round `s-1`** must represent stake at least `Q` from distinct pinned-epoch authority identities, counting each identity's stake at most once in this per-block parent set. Direct parents from older rounds are allowed but do not count toward this threshold; not every direct parent must be from round `s-1`. Multiple parent blocks from one equivocating authority likewise contribute that authority's stake only once to this set. The paper's §II-C, p. 4 preceding-round `2f+1` distinct-block-hash quorum is the source rule being adapted; it is **not an additional requirement** here, and there is no separate unweighted `2f+1` distinct-hash condition. This weighted replacement is a proposed model rule, not proven by the equal-weight paper. Validate strict decrease on every edge and the selected weighted predicate recursively for every relied-upon block/evidence.

**Genesis and round zero:** epoch 0 has exactly one deterministic virtual round-zero reference per authority. First compute the canonical execution state root; then a canonical genesis manifest binds the chain ID, epoch 0, committee authority IDs/keys/stakes, consensus parameter/version, and that root. The manifest digest is then used with the canonical authority ID and domain separation to derive each authority's virtual reference. This order avoids a cycle between the execution root, manifest, and references. The concrete canonical serialization, hash algorithm, execution-root algorithm/current availability, and atomic genesis setup are **open prerequisites/gates**; this ADR does not choose algorithms or claim the repository currently has a canonical root or atomic initializer. A virtual reference is a canonical synthetic leaf tied to the common manifest, not a normal signed, executable, or committable proposal. Its narrow validation exemption is that it need not carry an ordinary block signature or ordinary proposal payload/parent-validity proof: instead, validate its exact derivation from the accepted manifest digest and authority ID, and validate the manifest/genesis boundary itself. It may serve as a direct parent for round 1. An ordinary round-1 block is counted-valid only if its valid direct round-zero references represent at least `Q` stake from distinct authorities; all committee references represent `W`, but a subset must itself reach `Q`. A single genesis block is not a substitute for this multi-authority quorum. Genesis and epoch-boundary validity must be explicit; epoch transitions/rotation are deferred and not declared complete.

**Causal ancestry** follows ordered parent references recursively and is distinct from the immediate-parent set. Given the strict parent-edge round invariant, rounds strictly decrease along every nonempty ancestor path. For a target `(authority, round)`, a traversal uses the first encountered block for that author/round as specified by the paper’s depth-first `SupportedBlock` helper (Algorithm 1). Support is candidate-specific: the encountered block’s digest must equal the candidate digest. All blocks, signatures, parent links, rounds, and the traversal’s required ancestry must be validated and complete. Unknown, missing, pruned, or unresolved ancestry is **unknown**, never non-support or evidence of absence.

**Proposed counted-block validity:** every ordinary block whose stake is counted in a decision predicate must be authenticated, bound to the pinned epoch-0 committee, and satisfy the weighted direct-parent predicate above, including recursively validating every relied-upon parent block/evidence. Each authority contributes stake at most once to a block's direct-parent set, even if multiple equivocating parent blocks from it occur there; digest-specific support is a separate predicate and set. Older-round parents are permitted but do not satisfy the round-`s-1` parent threshold. Round-1 blocks use the validated synthetic round-zero references as specified above. Mixed-epoch, invalid, or incomplete evidence is invalid/unknown and cannot count. There is no additional paper-style unweighted distinct-hash quorum. Genesis validity and any future epoch-boundary rules must be specified and validated; absent a validated rule and evidence, blocks cannot be counted.

## 3. Decision predicates

The following predicates are the selected weighted adaptation of the Mysticeti-C model. Replacing the paper's preceding-round `2f+1` parent quorum with the `Q` stake predicate is a proposed model rule, not proven by the equal-weight paper. Every block/evidence item relied on by these predicates must itself be valid under §2, recursively, with the genesis exception narrowly defined there.

### 3.1 Support and certificates

For a counted-valid block `x` in round `r+1` and candidate `c` in round `r`, `supports(x,c)` holds exactly when the ordered causal traversal from `x` first encounters the block for `c.author` at round `r`, and that block is `c`. A complete traversal that encounters a different candidate establishes non-support for `c`; incomplete/unknown traversal establishes neither support nor non-support. This is block-specific causal support, not an unbound vote. The Q stake in `x`'s valid direct round-`r` parent blocks is a separate block-validity requirement; it is not a replacement for candidate-specific support. Multiple parent digests from one authority count once toward this per-block validity stake, while support remains digest-specific.

For a counted-valid round `r+2` block `x`, `IsCert(x,c)` holds iff its fully resolved, validated immediate-parent set contains valid round-`r+1` blocks supporting `c` authored by at least `Q` **distinct authorities by stake**. Count each authority once in this inner supporter set, even if multiple parent blocks or equivocations exist. Missing parent/evidence or incomplete ancestry makes the predicate unknown, not false. This candidate-support predicate is distinct from the counted-block validity threshold over `x`'s immediately preceding-round parents.

### 3.2 Direct decision

For candidate `c`, `SupportedProposer(c)` holds iff at least `Q` stake from **distinct authors of counted-valid round-`r+2` blocks** provide valid `IsCert(x,c)` evidence in the pinned evidence view and epoch. This outer certifier stake is separate from the inner `Q` stake of round-`r+1` supporters. A single authority cannot inflate either set by publishing multiple blocks. The block’s signature and epoch identity must be validated before its stake is counted.

Qualification is candidate-specific; it does not close a finite local candidate list. A fully validated `SupportedProposer(c)` certificate does, conditionally, exclude any later/conflicting fully validated direct certificate for another candidate `d` in the same slot, even across different valid prefixes. The certificate-based argument is: the two outer `Q` sets of distinct round-`r+2` certifier authors intersect in honest stake; a common honest round-`r+2` block would then have to satisfy both `IsCert(x,c)` and `IsCert(x,d)`. Its two candidate-specific inner `Q` sets of valid immediate round-`r+1` supporting parent authors also intersect in honest stake. Under one honest block per round and deterministic ordered first-encounter support, that honest round-`r+1` block cannot support both digests. This is a conditional, certificate-based direct-closure argument, not closure from an exhaustive or finite local candidate list. It requires a fixed pinned epoch/stake map, unique identities, checked `Q` and `B < W/3`, authentic complete recursively valid ancestry, the counted-block `Q`-stake immediately preceding-round parent-author predicate (older parents are allowed but do not count), strictly decreasing parent rounds, deterministic ordered first-encounter support, and one honest block per round. Genesis and epoch-boundary validity remain unresolved, so the argument does not settle those cases.

Only a fully validated direct certificate can supply this conditional closure. Missing certificate or ancestry/evidence remains unknown and waits; “exactly one currently known candidate” is never sufficient. If independently validated evidence appears to qualify two candidates, fail closed, leave the slot undecided, and raise an invariant alert rather than selecting by arrival order, digest, or another tie-break. This sketch does not establish candidate discovery, durable monotonicity, or complete cross-view slot agreement. Consensus implementation remains blocked on the open obligations in §4 and the implementation gate; the ordered output prefix cannot advance past an undecided slot.

### 3.3 Direct skip and empty proposer slots

The paper’s direct-skip prose describes a per-proposal skip pattern: for every proposal, observe `2f+1` subsequent blocks that do not support it or support no proposal (NDSS §III-B, p. 5). Algorithm 1 defines `SupportedBlock` by causal traversal but `SkippedProposer` by checking immediate-parent authors; the printed helper counts round-`r+1` blocks whose immediate parents contain no block authored by the scheduled proposer (lines 27–32, p. 7). These descriptions are not equivalent in the presence of equivocation, partial views, and empty slots.

This ADR selects the **printed-helper shortcut** as the project’s direct-skip adaptation: directly skip a scheduled slot only if `Q` stake from distinct authors of valid round-`r+1` blocks satisfies the following author-based aggregation. An authority contributes its stake at most once to this skip evidence if at least one of its counted-valid round-`r+1` blocks has a fully resolved, validated immediate-parent set containing no block authored by the scheduled proposer. Multiple qualifying blocks from one authority do not multiply its stake. An authority may independently appear once in a different candidate-specific support/certificate set; deduplication is within each evidence set. Unknown parent sets, unavailable ancestry needed to validate those sets, invalid blocks, or absent local data do not count as evidence. This is an explicit adaptation of the printed shortcut; it is not asserted to be identical to the paper’s prose or proven to preserve all paper properties. Safety of this aggregation across partial/different valid views, and proof that it cannot conflict with a commit, remain open requirements.

Because `SkippedProposer` inspects immediate parents while `supports` is defined over causal ancestry, the following structural lemma is needed. **Under the strict parent-edge round invariant**, an `r+1` block can causally reach a round-`r` proposer candidate only if that candidate is an immediate parent: if the immediate parent is older than `r`, all its ancestors are older still; if it is round `r`, its own parents are older than `r`, so no round-`r` ancestor can occur below it. Therefore, if an `r+1` block has no immediate parent authored by the scheduled proposer, it cannot support any round-`r` candidate for that proposer. This lemma is a derivation from the edge invariant and the round-specific candidate definition, not a standalone statement in the paper.

The converse does not identify a candidate: a proposer-authored immediate parent may be from an older round, or may be a different equivocating digest at round `r`; its presence alone does not establish support for a particular candidate. The helper’s candidate-specific traversal must still encounter that candidate digest. Quorum intersection by itself does not establish direct-skip versus direct/indirect-commit incompatibility; the conditional scope and remaining assumptions are in §4.2 and the implementation gate.

An empty proposer slot is not skipped merely because no candidate is locally known. It still requires the same explicit quorum evidence under the selected shortcut. This sacrifices decision availability when the evidence is unavailable; it avoids converting absence of data into proof of absence. If direct commit and direct skip evidence conflict, leave the slot undecided and report an invariant failure; do not resolve by ordering or a tie-break.

### 3.4 Indirect decision and anchor

If direct predicates do not decide the target slot, examine later scheduled proposer slots in deterministic protocol order. The **anchor** is the first later leader slot with round `> r+2` whose status is committed or undecided; only explicit, terminal, provenance-backed skip statuses may be passed. An absent, missing, unknown status, or a skip whose evidence/provenance is incomplete stalls the scan and leaves the target undecided; it is not silently passed as a skip. An undecided anchor likewise stalls. This matches the paper’s indirect rule: the first later slot beyond the decision round that is already to-commit or undecided (§III-B, pp. 5–6; Algorithm 3, lines 21–31, p. 7). With three-round waves, the earliest anchor round is `r+3`. The explicit-skip requirement is necessary for each differing-anchor transfer premise in §4.2: a later-anchor view must be able to justify the earlier slot it passed as a terminal skip in that same view.

For this rule, every terminal commit must carry exact-digest-bound provenance identifying its target candidate `(authority, round, digest)`. For a direct commit, provenance identifies the actual counted-valid round-`r+2` certifier block digest(s) in `SupportedProposer(c)` and, for each certifier, the exact round-`r+1` immediate-parent block digest(s) whose validated candidate-specific support establishes `IsCert(x,c)`. The outer certifier and each inner supporter set must be identity-deduplicated and meet their separate `Q` thresholds; all cited blocks and relied-upon ancestry are recursively validated. For an indirect commit, provenance identifies the exact committed anchor block digest **and recursively includes that anchor's own terminal-commit provenance**; it also binds the anchor's complete recursively validated ancestry and parent-edge link to an exact round-`r+2` certificate block digest for the target candidate, together with that certificate's validated `IsCert` support evidence. The indirect `CertifiedLink` remains existential and does not acquire an outer-`Q` requirement. A persisted status/hash, or evidence identifying only a slot or author without these exact digests and links, is not decision provenance. Missing provenance or incomplete ancestry/evidence leaves the status unresolved/unknown and the target undecided; it is never evidence for a skip.

If the first such anchor is undecided, the target remains undecided. If it is committed to block `b_anchor`, enumerate the target slot’s candidates found in the complete, validated causal ancestry of `b_anchor`. For each candidate `c`, `CertifiedLink(b_anchor,c)` holds existentially iff **one** valid round-`r+2` block certifying `c` occurs in that complete ancestry. `CertifiedLink` itself does not require `Q` stake of certifier blocks. Make one slot-level decision over this complete candidate set: if required ancestry/evidence or candidate enumeration is incomplete, remain undecided; if the complete set contains zero linked candidates, indirectly skip; if it contains exactly one linked candidate, indirectly commit it; if multiple candidates are linked/commit-qualified, remain undecided and raise the same invariant alert as for multiple direct qualifiers. Never skip merely because one candidate is unlinked when another links. The Q threshold applies to direct commit’s outer certifier set, not to this existential link predicate. Absence from incomplete data is not a negative claim.

The paper’s Algorithm 1 `CertifiedLink` checks for a certificate block in the decision round linked to the anchor; its `Link` follows parent edges (§III-D, Algorithm 1, lines 39–42, p. 7). For this adaptation, “no link” is only conclusive after complete anchor ancestry and complete candidate/evidence enumeration have been established. A missing/pruned/unresolved block cannot establish absence. The complete anchor ancestry defines the candidate set for this indirect evaluation, not a claim that candidates absent from some other local view do not exist. Multiple linked candidates are handled fail-closed as above; indirect processing cannot silently choose one.

### 3.5 Ordering and output prefix

These local ordering rules do not establish cross-view agreement. With the same anchor block, validators obtain the same slot aggregation only if they validate its full ancestry and perform complete candidate enumeration deterministically. Different anchors reduce conditionally to agreement on the earlier slot's terminal status: the view selecting the earlier anchor treats it as committed or undecided, while a view selecting a later anchor must treat that earlier slot as skipped. Proving those statuses compatible and immutable across views is still open. Complete ancestry relative to each validator's chosen anchor does not establish that all validators chose the same anchor or status; fail-closed multiple-candidate handling and a locally blocked output prefix likewise do not by themselves establish cross-view agreement.

Evaluate candidates/slots with a deterministic schedule and protocol ordering independent of message arrival. Persist slot statuses, including later slots, as evidence permits; an undecided earlier slot does not necessarily prevent internal evaluation or persistence of a later status. However, the first undecided slot blocks advancement/emission of the ordered committed output prefix beyond it, even if later slots have locally evaluable outcomes. Skip outcomes are explicit and persistable; they are not omitted from outcome history or cursor state. This preserves the paper’s committed-sequence prefix condition (Algorithm 3, lines 16–20, p. 7; §V-A, Lemma 7, p. 11) without conflating output-prefix advancement with internal slot evaluation.

Accordingly, prefix comparability across views is only conditional: terminal statuses must agree, and each view must stop emission at its first undecided slot. Neither condition nor the resulting cross-view prefix proof is established by this draft.

## 4. Safety assumptions and proof status

### 4.1 Assumptions required by the design

Any future implementation and proof must state and enforce at least these assumptions:

1. Static epoch 0: fixed committee, stake map, identity/key binding, proposer schedule, and epoch for all evidence in a decision; checked positive `W`, and Byzantine stake `B < W/3`. Every parent edge strictly decreases rounds. Every counted-valid ordinary block in round `s>0` has valid direct round-`s-1` parents representing at least `Q` stake by distinct epoch-0 authority identity, counted once per identity for that block; older-round parents are permitted but do not count. The paper's §II-C preceding-round `2f+1` distinct-hash rule is the source being adapted, not an additional normative condition. This `Q` replacement is a proposed model rule, not proven by the equal-weight paper. Round-1 validity uses the synthetic round-zero refs and genesis commitment specified in §2. There is no epoch transition in this scope; transition/rotation validity remains deferred and open.
2. One honest block per authority per round/slot, with signer-side anti-equivocation enforcement. Byzantine authorities may equivocate; all candidate blocks must be retained and enumerated.
3. Every counted ordinary block has authenticated author/signature and valid round/parent structure, including the strict parent-edge round invariant; its Q-stake threshold over valid direct round-`s-1` parents is established in a pinned epoch-0 evidence view, with each parent authority counted once per block. Older-round parent references are permitted but do not satisfy the threshold. All parent blocks and other evidence needed for a positive **or negative** decision are complete and recursively validated. Candidate-support predicates (such as `IsCert` and `SkippedProposer`) remain distinct from counted-block validity. Round-zero refs receive only the narrow synthetic-leaf validation exemption in §2.
4. Causal persistence: the conditional certificate-persistence sketch in §4.2 applies only to a Q-outer direct-qualified certificate and requires the weighted Q-parent predicate on every valid intervening block, not only blocks counted in a decision set. Still specify and prove the required ancestry/completeness and ordered first-encounter behavior, including why adding later ancestry cannot make an honest traversal encounter a different same-author/round block before the target candidate. Specify and prove genesis-manifest, virtual-reference, genesis-boundary validity and persistence rules; evidence cannot silently cross an epoch boundary. Concrete canonical serialization/hash and execution-root algorithms and atomic genesis setup are open gates.
5. Inner supporter and outer certifier sets are distinct identity-deduplicated sets with the correct, separate `Q` checks. Evidence is evaluated in the same r+1/r+2 window and against the same scheduled slot/candidate.
6. All validators use deterministic schedule, anchor selection, candidate aggregation, conflict handling, and ordered prefix emission. Safety must be proved across **different valid local DAG prefixes**; validators are not assumed to have equivalent snapshots or equivalent evidence. Unknown evidence never counts as non-support or absence, and local finite candidate lists do not establish closure.
7. Persisted decisions, evidence, relevant DAG and equivocation state, epoch/schedule and signer state survive restart without rollback or reinterpretation; corruption is detected and fails closed.

### 4.2 What is and is not established

The weighted quorum arithmetic is valid under the stated fault model: any two `Q`-stake sets intersect in at least `2Q-W > W/3 > B` stake. This establishes honest pairwise overlap, not by itself causal persistence or the Mysticeti-C safety theorem for this adaptation.

Oracle’s weighted Lemma 1/3/6 reviews and the reconciled `ora-26`, `gen-17`, and `ora-27` consults were conditional sketches, not proof. The weighted analogue of paper Lemma 1 (NDSS §V-A, pp. 10–11) was sketched conditionally on each counted block having authenticated, valid direct immediately preceding-round parent blocks from distinct identities with total stake `Q`, with all evidence for each claim fully validated against one pinned epoch-0 stake map and a complete local evidence view, and one honest block per round. This does not require validators to have identical evidence snapshots: different valid prefixes remain subject to the separate cross-prefix proof obligation, and absent evidence stays unknown. The weighted author-stake parent predicate is the proposed replacement for the paper’s §II-C `2f+1` distinct-hash parent rule, not an additional condition or a proven transfer. Older-round parents remain permitted but do not satisfy the weighted threshold. Genesis commitment, virtual-reference and epoch-boundary rules remain open. Equivocated alternatives, duplicate-author counting, mixed epochs, or incomplete evidence break the transfer.

The weighted Lemma 3 sketch needs both inner supporter `Q` and (for direct commit) outer certifier `Q`. Under the stated pinned-epoch, unique-identity, checked-threshold, authentic complete recursively valid ancestry, counted-block validity, strict-round-decrease, deterministic first-encounter, and honest-one-block-per-round premises, a fully validated direct `SupportedProposer(c)` certificate conditionally excludes another direct certificate for a different candidate: outer certifier sets intersect in an honest round-`r+2` author/block, and that block's two candidate-specific inner supporter sets would have to intersect in an honest round-`r+1` block supporting both digests, which deterministic support forbids. This is a certificate-based direct-closure sketch, not a local-list closure theorem; missing evidence waits. Genesis and epoch-boundary validity remain unresolved.

There is also a conditional causal-persistence sketch for a Q-outer direct-qualified certificate. It additionally assumes the weighted Q-parent predicate is enforced for every valid intervening block, not merely the blocks counted in decision sets. Every valid round-`r+3` block then has a `Q`-stake set of distinct authors among its immediately preceding-round parents; that set intersects the certificate's `Q` outer certifier authors in honest stake. By one honest block per round, the common author's round-`r+2` block is the certificate block, so it occurs in the round-`r+3` block's ancestry. Every valid later block has `Q` valid preceding-round parent authors, and all valid blocks in the preceding round already carry that certificate in their ancestry; induction therefore preserves it through every later valid block. Consequently, any same-epoch later valid committed anchor with complete ancestry has a `CertifiedLink` for candidate `c`; an undecided anchor still stalls. Under these premises, direct commit cannot be followed by a zero-link indirect skip. This does **not** establish persistence for an arbitrary existential certificate without an outer quorum: for example, with `W=4`, `Q=3`, a single certifier author `a` (stake `1<3`) can certify candidate `p`, while a later valid block can have preceding-round parent authors `{b,c,d}` and omit `a`'s certificate block. This is only a fragment illustrating the missing outer-quorum premise, not a full protocol counterexample.

The weighted Lemma 6 sketch depends on the anchor, complete ancestry, deterministic candidate aggregation, and ordered-prefix behavior. With identical anchor blocks and complete validated ancestry/candidate enumeration, slot aggregation is identical. Across differing anchors, the question conditionally reduces to compatibility and immutability of the earlier slot's terminal status; those properties remain open. The direct-skip versus indirect-commit incompatibility is conditionally supported by the Q-intersection argument plus the strict-edge immediate-parent structural lemma in §3.3: the honest overlap cannot be both a skip contributor and an inner supporter. This does not establish broader skip aggregation safety across partial views. Prefix comparability follows only if terminal statuses agree and emission stops at the first undecided slot. Later resolution of undecided slots, durable monotonicity, complete-prefix proof, liveness, genesis/epoch rules, and recovery remain open. Indirect candidate discovery is defined here only for complete validated committed-anchor ancestry; these consults are internal review provenance, not formal theorems or Gate 1 approval.

Under a fixed epoch, authenticated and fully validated evidence, distinct-author `Q` sets, and the honest one-block-per-round assumption, the structural lemma in §3.3 plus quorum intersection establishes a **conditional, pairwise skip-versus-candidate-support incompatibility**: the weighted `Q` skip set and the `Q` inner candidate-support set intersect in an honest author, who cannot provide both a skip block and a supporting block. This applies to direct candidate support and to the inner round-`r+1` support set of an indirect certificate. This pairwise implication is conditionally established, not a standalone paper theorem. It does not prove causal persistence beyond the Q-outer certificate sketch, closure from local candidate lists, durable monotonicity, cross-view anchor/prefix consistency, broader equivocation aggregation, recovery, whole-protocol safety, or liveness; those remain blocked obligations.

**Conditional finite-prefix cross-view theorem/sketch (reconciled Oracle `ora-35`; finite analysis `gen-20`; endpoint inventory includes `ora-42`, `gen-23`, `ora-44`, and `gen-24`):** this is a conditional, non-formal induction sketch, not a proof, exhaustive analysis, or Gate/implementation approval. Fix two finite valid prefixes `P` and `Q` with the same epoch, stake map, proposer schedule, and protocol rules. Do **not** assume that `P` and `Q` agree. For every compared slot and recursively cited slot, require in each prefix a locally valid, unambiguous, terminal outcome with complete, valid, fully provenance-backed decision derivation/evidence in that prefix. Positive and negative evidence must be complete and recursively validated against that prefix's pinned epoch; unknown evidence is not terminal. The endpoint incompatibility lemmas listed below are additional premises to be established, not results proved here. The existing weighted-threshold, block-validity, support, genesis, persistence, and other assumptions above remain applicable; in particular, the weighted `Q` parent predicate must hold on every relevant and intervening ordinary block, with one honest block per round and strictly decreasing parent rounds. This local validity and provenance requirement concerns each frozen prefix separately; it is not cross-view agreement.

The required endpoint premises cover all of the following. Unless stated otherwise, “opposite” means commit versus skip for the same slot, and each item requires terminal outcomes, not `undecided` or unknown.

1. **Direct/direct conflict:** two direct commits to different candidates are incompatible by the conditional outer-`Q`, then inner-`Q` honest-intersection argument; direct commit versus direct skip is incompatible by the conditional inner-`Q`/skip intersection and §3.3 strict-edge structural lemma. Two skip outcomes agree.
2. **Direct skip / indirect commit:** the direct skip's `Q` no-proposer evidence must be incompatible with the indirect committed candidate's inner-`Q` support witness, using the §3.3 structural lemma and complete, provenance-backed indirect evidence.
3. **Direct commit / indirect skip:** incompatibility requires the Q-outer direct-certificate persistence premise: the certificate must persist into every later valid ancestry used by the indirect decision, so a complete later committed anchor cannot validly yield zero links. The persistence sketch above is conditional and does not establish this premise.
4. **Direct commit / indirect commit to different target candidates:** exact-digest `IsCert` provenance for each terminal commit, including each certificate's identity-deduplicated inner-`Q` supporter set, is sufficient for the conditional inner-`Q` intersection incompatibility: an honest common round-`r+1` supporter cannot support both target digests. Unlike direct-commit/indirect-skip (item 3), this endpoint does not require Q-outer certificate persistence. The indirect decision still requires complete candidate enumeration; incomplete evidence is unknown and must not be treated as a negative result.
5. **Indirect outcomes with the same identical anchor block/digest:** complete validated ancestry and deterministic, complete candidate aggregation must give the same target-slot result. Same anchor slot but different anchor digests requires the `ora-39` exact-digest inner-`Q` witness, with terminal-commit provenance validated as required by §3.4; this is an endpoint premise, not discharged merely by saying the anchor slot is the same.
6. **Indirect outcomes with different anchor slots:** use the transfer induction below, rather than assuming anchor/status agreement.
7. **Pairs with the same skip result:** they agree; this does not discharge a commit/skip endpoint or establish status compatibility for other slots.

For differing-anchor transfers, form a finite, provenance-closed index set `U` containing the target; all terminal commit/skip statuses used; every explicit terminal skip slot passed over in selecting an anchor; every recursively cited anchor and status-provenance slot; and any authenticated checkpoint terminal-history range used. `U` is only an index bound: keep `P` and `Q` evidence separate throughout, and never merge their evidence into a purported valid view. Let `H` be the maximum protocol-order index in `U`. In each transfer, the view selecting the later anchor must itself contain an explicit terminal, provenance-backed skip for the earlier anchor slot it passed; the other view must itself contain an explicit terminal, provenance-backed commit for that earlier slot. Both statuses and their derivations must be valid in their respective fixed prefixes. Missing/incomplete skip evidence cannot satisfy this premise; per §3.4 it stalls anchor selection. Transfer the comparison to that earlier anchor slot, whose round is strictly later than the current target because the anchor is beyond `r+2`. Thus `H - index(target)` strictly decreases at every transfer (by at least 3 for three-wave rounds), with every transferred-to slot inside `U`.

At a maximal slot in `U`, no terminal indirect decision can rely on a later committed anchor without that anchor and its cited status provenance also belonging to `U`; the comparison therefore reaches one of the endpoint premises above (including the direct/mixed cases), or the two outcomes are the same skip. If all endpoint premises hold, this finite induction conditionally derives that these fixed prefixes cannot give opposite terminal commit/skip outcomes for a compared slot or conflicting committed candidates for that slot. The induction does not prove its endpoint premises, local outcome validity, complete/negative evidence, or any cross-view assumption.

Keep four claims distinct: **local status coherence** means outcomes are unambiguous and justified within one frozen prefix; it does not imply cross-view agreement. The theorem sketch compares two frozen prefixes and conditionally transfers indexed terminal statuses; it says nothing about **evolving-view monotonicity** as new evidence arrives. Nor does it establish **durable restart recovery** or provenance-preserving persistence after crashes. An undecided earlier slot still blocks that view's ordered output-prefix advancement, while another view may resolve past a skip; unknown is neither terminal skip nor commit. Prefix comparability, cross-view terminal-status compatibility, evolving monotonicity, durable recovery, complete-prefix behavior, and liveness remain open. This sketch establishes no endpoint premise, formal combined Mysticeti proof, safety, liveness, or implementation/Gate approval.

Explicit proof obligations remain: formalize and verify the conditional direct-certificate closure premises, including genesis/epoch validity; prove durable monotonicity and safe decisions across different valid local DAG prefixes; prove the per-author `SkippedProposer` aggregation is safe across partial views beyond the conditional pairwise skip/support implication; and complete the direct/indirect and combined safety argument under equivocation. For differing anchors, prove earlier-slot terminal status compatibility/immutability, completeness of the finite `U` closure (including authenticated checkpoint history where applicable), later resolution of undecided slots, and prefix comparability; same-anchor complete ancestry alone is insufficient. Prove complete-prefix behavior, liveness/backpressure under unavailable or incomplete evidence, and recovery without outcome reinterpretation. Validate and enforce the strict parent-edge round invariant on all evidence; the structural lemma alone does not discharge weighted block validity or wider skip/commit obligations. Paper Lemmas 1, 3, 4–6 and Theorem 1 (total order) are references for equal-weight Mysticeti-C, not proofs of this weighted, modified-skip design. No complete Mysticeti safety or liveness proof is claimed here, and no Gate 1 approval is granted.

**Liveness is not established.** The selected validity and decision rules permit a no-progress witness even with complete, timely evidence. The reconciled `ora-46`/`gen-25` consultations are conditional reviews, not theorem evidence. For a compact witness within the rules currently specified here, take four equal-stake authorities, `W=4`, `Q=3`, and no Byzantine stake. In a round, each authority produces exactly one valid block, and each produced block has valid parents from three distinct authorities in the prior round, satisfying the selected `Q`-parent validity rule. For a candidate `c` in round `r`, exactly two distinct authors' round-`r+1` blocks have `c` as a parent and support `c`; the other two distinct authors' blocks have no immediate parent authored by the scheduled proposer. Thus the candidate-specific round-`r+1` support aggregate and the printed-helper skip aggregate each have stake `2 < Q` (while `supports(x,c)` remains a per-block predicate). Since only two distinct authors support `c`, no counted round-`r+2` block can have `Q` stake of supporting parents, so `IsCert(x,c)` is false for every such block. This is a witness that the specified validity/decision abstraction alone does not ensure progress. Repeating this pattern across slots is permitted by the rules currently stated in this ADR, but is **not** a full-paper post-GST primary-proposer liveness execution.

The distinction matters: NDSS §V-B's post-GST liveness argument includes production and voting conditions not selected or specified by this ADR. Under the paper's primary proposal/voting policy, honest validators vote for an honest primary; Lemmas 9–10 establish the honest primary's votes/certificate. In this all-honest `W=4` instance, an honest primary proposal would receive four votes, so the two-support pattern above cannot persist for primary proposals under that policy. Lemmas 11–12 then use round-robin windows, including three consecutive honest primaries in a `3f+3` window, to resolve earlier undecided slots; Theorem 2 states eventual commit. An isolated non-primary candidate that lacks `Q` support is not, by itself, a contradiction of the paper's overall liveness result. These equal-weight paper arguments do not automatically transfer to this weighted adaptation or its selected modified predicates, and this ADR does not adopt the paper's additional production/vote policy, choose a proposer schedule or liveness-sufficient window, or claim weighted liveness.

Do not infer a liveness-sufficient schedule from the current static-epoch assumption or from the equal-weight paper proof. That proof relies on its primary production/vote policy and round-robin windows, including the `3f+3` window argument; neither is adopted here, and neither transfers automatically to the weighted/modified predicates. Primary production/vote conditions and schedule/window sufficiency therefore remain open proof/spec obligations. Any future conditional liveness claim must also establish fair post-GST production, delivery, and processing; valid `Q`-parent availability round by round; and eventual complete decision, negative, anchor, and ancestry evidence. Fail-closed unknown handling remains safe but can stall forever when evidence is incomplete. The no-progress witness exposes insufficiency of the rules currently specified, not a refutation of full Mysticeti-C; resolving the separate decision-rule/parent-selection gap remains open.

## 5. Persistence and recovery requirements

Consensus state must be sufficient to deterministically reconstruct the exact decision history, not just a committed round number. Persist or durably reconstruct:

* committee epoch, unique authority-ID/key/stake map, checked `W`, `Q`/`V`, and proposer schedule/parameters;
* all relevant authenticated DAG blocks and parent links, including every candidate for each `(authority, round)` slot, evidence windows, completeness/availability status, and per-author equivocation aggregation state;
* immutable commit **and skip** outcomes, invariant-failure/undecided states, later-slot statuses as needed for deterministic anchor evaluation, and the deterministic output cursor/prefix;
* enough canonical ordering/output replay metadata to reproduce committed sub-DAG delivery exactly once;
* signer anti-equivocation state binding authority, epoch, round/slot, and signed digest.

Pruning may not remove evidence still needed to decide or verify an outcome unless a separately specified authenticated checkpoint preserves the necessary proof. Missing, corrupt, or pruned evidence cannot imply non-support, empty slot, absent certificate, or absence of a `CertifiedLink`; it stalls the affected decision or recovery and raises an operational error. A late valid block may add evidence to an undecided slot but must never flip a durable commit/skip. If newly observed evidence conflicts with an immutable outcome, report a safety/integrity failure; do not rewrite history.

**Informative current implementation status (not a normative requirement or approval):** storage persists decided-round-to-leader-hash records and DAG blocks; startup reads these records to reconstruct committed sub-DAGs. It does not persist/recover skip, undecided, or invariant-failure statuses, the decision predicate/certificate evidence, or the ordered output cursor/committer state. Thus this is not an absence of all commit records or DAG evidence, but the persisted commit record is insufficient to reconstruct the complete decision history required above. The execution marker provides transactional effect deduplication, but there is no atomic outcome-plus-delivery-cursor transaction. Signer anti-equivocation state and committee/epoch persistence are also absent. These gaps do not relax the normative requirements above and keep consensus implementation blocked.

## 7. Migration and compatibility impact

No wire format, consensus behavior, execution behavior, or network activation change is authorized by this draft. A future implementation would be a consensus state-machine and persistence redesign: candidate-aware slot/DAG indexing, digest-bound authenticated evidence, stake/epoch validation, ordered causal-support queries, durable commit/skip/cursor state, fail-closed decision logic, and recovery/replay. It would also require authenticated block/vote or equivalent evidence delivery and real multi-validator configuration; existing DAG linearization is not itself Mysticeti-C protocol slot ordering. Any protocol-versioning, state migration, checkpoint, or mixed-version policy is open and must be specified before rollout. The singleton committee is trusted/non-BFT and cannot demonstrate BFT safety or liveness.
